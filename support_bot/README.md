# Бот поддержки

Каталог содержит код бота сотрудников, но не отдельную систему запуска. Основной и
support-бот используют **общий `.env` в корне репозитория** и запускаются **в одном контейнере**.

## Переменные

В корневом `.env` используются:

- `SUPPORT_BOT_TOKEN` — отдельный токен бота поддержки;
- `SUPPORT_ADMIN_IDS` — администраторы, управляющие сотрудниками через `/admin`;
- `SUPPORT_STAFF_IDS` — необязательные начальные сотрудники;
- `SUPPORT_POSTGRES_*` — база поддержки на общем PostgreSQL-сервере;
- `POSTGRES_*` — основная база Тайби, откуда берутся обращения и заказы.

В Docker Compose сетевые адреса уже заданы: оба бота и базы доступны по имени сервиса `db`.
Дополнительные файлы окружения внутри `support_bot/` не нужны.

## Базы и очереди

В основной базе `taibi`:

- `support_conversations` — диалоги Telegram/Avito;
- `support_inbox` — сообщения и события для поддержки;
- `support_outbox` — ответы и действия для основного бота.

В базе `tybee_support` хранятся сотрудники, обращения, назначения и история переписки.
`source_event_id` исключает повторный импорт, а атомарный SQL UPDATE не позволяет двум
сотрудникам взять одно обращение одновременно.

## Работа сотрудников

- `/start` — меню;
- `/requests` — доступные и назначенные обращения;
- `/admin` — управление работниками для администратора;
- `/order "Название" [описание] сумма` — счёт клиенту с подписанной ссылкой Robokassa;
- `/ban`, `/pardon` — блокировка и разблокировка клиента.

Для действий с заказом сотрудник сначала открывает назначенное ему обращение. Прямые
обращения в support-боте также поддерживаются, но действия с основной БД для них недоступны.

## Запуск

Из корня репозитория:

```bash
docker compose up --build
```

Или без Docker:

```bash
python -m scripts.run_bots
```

Отдельные Dockerfile, Compose и `.env` этому каталогу не требуются.
