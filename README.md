# Тайби: боты-обложки и панель сотрудников

Тайби — сервис работы с заказами и клиентской поддержкой. Клиенты пользуются Telegram-ботами с разным оформлением, а сотрудники работают на сайте. Сайт заменяет прежнего главного бота: в нём ведутся диалоги, заказы, сотрудники, обложки и финансы. Данные хранятся в общей базе PostgreSQL.

В проекте также есть код и настройки для Avito и Robokassa. Доработкой и подключением этих интеграций занимается другая команда; наличие разделов и обработчиков само по себе не подтверждает готовность интеграций к эксплуатации.

## Состав системы

| Компонент | Назначение |
| --- | --- |
| Боты-обложки | Клиентские Telegram-боты: витрина, оформление заказов, профиль и переписка с поддержкой. У каждой обложки свой токен и оформление. |
| Панель сотрудников | Сайт на FastAPI и React: поддержка, работа с заказами, управление обложками, сотрудниками, каталогом и финансами. Разделы зависят от роли. |
| Бот входа | Отдельный Telegram-бот для входа сотрудников, приглашений и уведомлений. Это не клиентская обложка. |
| PostgreSQL | Общая база клиентов, заказов, сотрудников, переписки и других данных. |
| Фоновые обработчики | Процесс ботов обрабатывает исходящие сообщения и рассылки; процесс сайта переносит входящие события в диалоги поддержки. |

В Docker Compose компоненты запускаются как сервисы `db`, `bot` и `site`. Процессы `bot` и `site` используют общую базу и каталоги `covers/` и `data/`.

## Что видит клиент

### Главное меню и заказ

У каждой обложки свои название, тексты, кнопки, подписи статусов и баннеры. Клиенту доступны следующие сценарии:

- **Заказ по артикулу:** клиент вводит шестизначный артикул. Если товар найден в каталоге, создаётся заказ с его названием и ценой и показывается предложение оплаты. Если товар не найден, клиенту предлагается персональная заявка.
- **Персональная заявка:** клиент описывает товар. Бот создаёт заказ, открывает диалог и передаёт заявку в поддержку сайта.
- **Mystery Box:** клиент выбирает доступный бокс и переходит к оформлению и оплате.
- **Поддержка:** клиент открывает диалог и общается с командой в Telegram; сотрудники отвечают с сайта.
- **Профиль:** данные клиента, ссылка на оферту и последние заказы. Количество заказов ограничено `PROFILE_ORDERS_LIMIT`; они выводятся от новых к старым.

В конфигурации обложки предусмотрены 16 подписей статусов: новый, ожидает оплаты, проверка оплаты, оплата подтверждена, отклонён, в работе, принят, выкуплен, доставляется в Россию, на таможне, доставляется по России, ожидает получения, получен, оформляется возврат, возвращён и отменён. Доступность переходов определяется правилами заказа и правами сотрудника. Уведомления об изменении статуса отправляются через бота.

Счета и автоматическое подтверждение оплаты зависят от настройки и доработки Robokassa. Без работающей интеграции не следует считать процесс оплаты готовым.

### Как заказ попадает к сотрудникам

Персональная заявка создаёт заказ и событие для поддержки. Обработчик сайта переносит событие в клиентскую ветку. Сотрудник видит диалог и связанные с клиентом заказы с учётом своих прав. Заказ по артикулу создаётся при нахождении товара; сам по себе переход к оплате не следует путать с подтверждённой оплатой или новым сообщением в поддержку.

Если заявка подтверждена клиенту, но не появилась на сайте, проверьте оба процесса и базу:

```bash
docker compose ps
docker compose logs --tail=200 bot
docker compose logs --tail=200 site
docker compose logs --tail=100 db
```

Убедитесь, что оба приложения подключены к одной базе, сайт запущен, сотрудник имеет доступ к поддержке, а поиск и фильтры диалогов не скрывают нужную ветку. Ошибки обработки сообщений или доставки должны быть исследованы по журналам; повторная отправка заявки без проверки может создать дубликат.

### Интерактивный гайд

В меню есть кнопка «Интерактивный гайд»: короткое знакомство с платформой, собранное под роль сотрудника. Это тур по настоящему интерфейсу: страница слегка затемняется, нужная кнопка или раздел подсвечиваются рамкой, а рядом всплывает небольшая панель со стрелкой к этому элементу — она встаёт сбоку, снизу или сверху, смотря где есть место, и никогда не закрывает подсветку. Гайд сам открывает нужный раздел (в том числе конкретную ветку диалога и вкладку «Финансов»), прокручивает страницу к элементу и не закрывает уже открытые окна. Шагов 6–12 — смена, обращения, ответ клиенту, новый диалог, заказы, деньги, команда, боты. Листать можно кнопками, стрелками клавиатуры или точками-шагами. На телефоне меню разделов открывается на весь экран (страница под ним не прокручивается), панель гайда прижимается к нижнему краю, а список разделов подстраивается так, чтобы подсвеченный пункт был виден. Подсвеченный элемент остаётся рабочим: например, вкладку «Выплаты» можно нажать прямо во время тура. При первом входе гайд открывается сам; после закрытия он больше не появляется и остаётся доступен из меню.

### Лидеры

Раздел «Лидеры» открыт всем сотрудникам и показывает рейтинг поддержки за текущий день, неделю (с понедельника) и месяц по МСК: сообщения, приёмку новых клиентов, оплаченные заказы, отзывы на максимальную оценку, закрытые диалоги, медиану первого ответа и время на смене.

Баллы рейтинга: сообщение — 1, новый клиент — 5, оплаченный заказ — 10, отзыв — 20. Это только соревнование, деньги считает раздел «Финансы». Данные обновляются каждые 30 секунд, своя строка подсвечена.

### Зарплата саппорта

Раздел «Финансы → Зарплата саппорта» считает вознаграждение поддержки за календарный месяц (МСК) и одной кнопкой проводит его в баланс сотрудника:

| Часть | Как считается |
| --- | --- |
| Оклад | Фиксированная сумма из карточки сотрудника («Сотрудники» → Изменить → Оклад). |
| Оплата за диалоги | Исходящие сообщения поддержки × ставка 0,50–1,00 ₽ и приёмка новых клиентов × ставка 3,00–5,00 ₽. Ставки динамические: берётся коэффициент качества за месяц. |
| Премия за заказы | 2,5 % от суммы оплаченных заказов, где сотрудник указан как владелец ветки на момент оплаты. Возвращённые заказы не учитываются. |
| Премия за отзывы | 100 ₽ за каждый подтверждённый отзыв на максимальную оценку (Avito, Telegram, Яндекс). Отзывы вносятся в том же разделе. |
| Штрафы | Уменьшают премию, но не ниже нуля. Сами штрафы уже проведены отдельными операциями в балансе; если сумма штрафов больше премии, премия обнуляется, а остаток остаётся в балансе. |

Коэффициент качества = 0,5 × скорость первого ответа + 0,5 × полнота ответов. Скорость сравнивается с порогами «быстрый»/«медленный» ответ, полнота — со средней длиной ответа относительно эталонной. Коэффициент 1 даёт верхнюю ставку, 0 — нижнюю. Ставки, пороги и минимальная выплата настраиваются кнопкой «Ставки».

Начисление создаёт две операции — «Зарплата» (оклад + диалоги) и «Премия» (заказы + отзывы) — с периодом `ГГГГ-ММ`. Повторное начисление за тот же месяц блокируется, ошибочное отменяется сторно-операциями кнопкой «Отменить начисление». Заявка на выплату меньше 1 500 ₽ отклоняется; исключения проводит финансовый менеджер.

### Смены поддержки

Сотрудник начинает и завершает смену в панели. Новая или неназначенная ветка автоматически распределяется среди подходящих активных сотрудников на смене с учётом числа открытых веток. Если подходящих сотрудников нет, ветка остаётся без назначения.

Смена может завершиться автоматически, если панель перестала подтверждать присутствие, сотрудник не проявляет активности или клиент слишком долго ждёт в неоткрытой ветке. Неотвеченные обращения и незавершённые следующие шаги возвращаются в очередь. Пороги задаются в `.env`:

| Переменная | По умолчанию | Условие |
| --- | ---: | --- |
| `SUPPORT_SHIFT_OFFLINE_MINUTES` | 3 | Нет подтверждения присутствия панели. |
| `SUPPORT_SHIFT_IDLE_MINUTES` | 15 | Нет активности сотрудника. |
| `SUPPORT_SHIFT_NO_REPLY_MINUTES` | 10 | Клиент ждёт в неоткрытой ветке при выполнении условий проверки. |

Значения — положительные целые минуты. После изменения перезапустите процессы.

### Диалог по инициативе поддержки

Кнопка «Написать клиенту» в списке обращений ищет не только по существующим веткам, но и по всем клиентам, которые открывали бота: по имени, `@username`, Telegram ID или `#номеру заказа`. В выдаче видно, ведёт ли уже диалог другой сотрудник, сколько у клиента заказов и когда он последний раз был в боте.

Отправить первое сообщение можно, если клиент не заблокирован, писал в Telegram и у него есть включённая обложка. Нужна активная смена: без неё панель предлагает начать смену и повторяет отправку с тем же ключом. Если диалог уже ведёт другой сотрудник, панель не перехватывает его, а открывает существующую ветку. Повторная отправка с тем же ключом не создаёт дубликат.

Диалог, начатый сотрудником, помечается системной заметкой и не считается «новым клиентом» в зарплате и рейтинге: само сообщение оплачивается и даёт балл как обычное. Если Telegram не даёт боту написать клиенту, панель различает причины: клиент заблокировал бота, ни разу не нажимал `/start` или удалил аккаунт.

## Подготовка к запуску

Понадобятся Docker с Compose, доступ к Telegram и созданные через BotFather токены клиентской обложки и отдельного бота входа. Для внешнего доступа к панели нужен домен с HTTPS и reverse proxy.

1. Создайте файл настроек:

   ```bash
   cp .env.example .env
   ```

2. Заполните в `.env` как минимум:

   - `POSTGRES_PASSWORD` — пароль PostgreSQL;
   - `TYBEE_BOT_TOKEN` — токен первой обложки `default`, если она ещё не создана;
   - `WEB_ADMIN_IDS` — числовые Telegram ID администраторов через запятую;
   - `WEB_LOGIN_BOT_TOKEN` — токен отдельного бота входа;
   - `WEB_SESSION_SECRET` — длинный случайный секрет сессий;
   - `WEB_PUBLIC_URL` — публичный HTTPS-адрес панели, используемый в ссылках бота и уведомлений;
   - `WEB_COOKIE_SECURE=true` для панели за HTTPS.

   Случайный секрет для сессий можно получить командой `python -c 'import secrets; print(secrets.token_urlsafe(48))'`. Не публикуйте `.env` и токены.

3. Запустите систему:

   ```bash
   docker compose up -d --build
   docker compose ps
   ```

4. Откройте панель через настроенный HTTPS-адрес либо локально через `http://127.0.0.1:8000`, если `WEB_PORT` не менялся. Откройте бота входа в Telegram и выполните вход с аккаунта, ID которого указан в `WEB_ADMIN_IDS`.

5. Проверьте обложку в разделе «Обложки», откройте её в Telegram и отправьте тестовую персональную заявку. Проверьте заказ и диалог на сайте, начав смену сотрудника поддержки.

Compose публикует панель, базу и порт вебхуков только на `127.0.0.1`. Для внешнего доступа настройте HTTPS-прокси; файл `compose.server.yml` дополнительно убирает публикацию порта PostgreSQL:

```bash
docker compose -f docker-compose.yml -f compose.server.yml up -d --build
```

При использовании второго файла применяйте те же `-f` к последующим командам Compose. Не включайте `DEV` на доступном извне сервере: этот режим позволяет войти без подтверждения Telegram под любым активным сотрудником, включая администратора.

### Вход сотрудников

Администраторы из `WEB_ADMIN_IDS` добавляются или поддерживаются при запуске сайта. Остальные сотрудники входят после добавления и приглашения; учётная запись должна быть активной.

- **Через бота:** кнопка входа открывает одноразовую ссылку в Telegram; пользователь подтверждает вход у бота, после чего исходная вкладка авторизуется.
- **Telegram Login Widget:** для домена необходимо настроить `/setdomain` у BotFather для бота входа.
- **Локальная разработка:** установите `DEV=true`, пересоздайте сайт и на странице входа выберите сотрудника из списка — он сгруппирован по ролям, поэтому можно проверить панель глазами любой из них; выбор запоминается в браузере. Вход выполняется без подтверждения Telegram, с правами выбранного сотрудника. Если администраторы не настроены, доступен локальный Dev admin. На продакшене оставьте `DEV=false`: тестовые сессии перестанут действовать после выключения режима. Старый параметр `WEB_DEV_LOGIN` поддерживается для совместимости, если `DEV` не задан.

Уведомления бот сможет отправлять сотруднику после того, как тот откроет бота и начнёт с ним диалог.

## Настройки окружения

Полный пример с комментариями — [.env.example](.env.example). Значения из `.env` используются обоими процессами; после изменения параметров пересоздайте сервисы командой `docker compose up -d`.

| Группа | Переменные и назначение |
| --- | --- |
| База данных | `POSTGRES_HOST`, `POSTGRES_PORT`, `POSTGRES_DB`, `POSTGRES_USER`, `POSTGRES_PASSWORD`. В Compose адрес базы внутри контейнеров задан как `db:5432`. |
| Обложки | `COVERS_ROOT`, `COVERS_RELOAD_SEC`, `SUPPORT_COVER_SLUG`, `TYBEE_BOT_TOKEN`; последний применяется при первоначальном создании `default`, далее токен хранится в её `config.yaml`. |
| Данные | `DATA_DIR` — каталог фотографий товаров и рабочих вложений. В Compose используются общие монтирования `./covers` и `./data`. |
| Заказы | `PROFILE_ORDERS_LIMIT` — сколько последних заказов показывать в профиле, по умолчанию 10; `UNBAN_FINE_RUB` — общая сумма штрафа для обложек с настройкой `shared`. |
| Смены | `SUPPORT_SHIFT_OFFLINE_MINUTES`, `SUPPORT_SHIFT_IDLE_MINUTES`, `SUPPORT_SHIFT_NO_REPLY_MINUTES` — пороги автоматического окончания смены. |
| Панель | `WEB_PORT`, `WEB_ADMIN_IDS`, `WEB_LOGIN_BOT_TOKEN`, `WEB_LOGIN_BOT_USERNAME`, `WEB_SESSION_SECRET`, `WEB_PUBLIC_URL`, `DEV`, `WEB_COOKIE_SECURE`. |
| Avito | `AVITO_SECRET_KEY`, `AVITO_WEBHOOK_URL`, `AVITO_WEBHOOK_PORT` и устаревшие настройки одного профиля `AVITO_ENABLED`, `AVITO_CLIENT_ID`, `AVITO_CLIENT_SECRET`, `AVITO_WEBHOOK_SECRET`. Подключение ведёт другая команда. |
| Robokassa | `ROBOKASSA_SHOP_ID`, `ROBOKASSA_PASSWORD1`, `ROBOKASSA_PASSWORD2`, `ROBOKASSA_HASH_ALGORITHM`, `ROBOKASSA_TEST`. Подключение ведёт другая команда. |

`TYBEE_ADMIN_IDS` оставлена для совместимости; управление сотрудниками и правами выполняется на сайте через `WEB_ADMIN_IDS` и роли сотрудников.

## Управление обложками

Обложка хранится в `covers/<slug>/`: файл `config.yaml` содержит токен, тексты, кнопки и подписи статусов, а каталог `banners/` — изображения. Шаблон находится в `app/covers/default_config.yaml`. Токены в `covers/` являются секретами: не добавляйте этот каталог в публичные архивы и репозитории.

Создавать и изменять обложки удобнее в панели. Процесс ботов проверяет изменения с интервалом `COVERS_RELOAD_SEC`, по умолчанию 10 секунд. Также доступны команды внутри контейнера:

```bash
docker compose exec bot python -m app.covers list
docker compose exec bot python -m app.covers check default
docker compose exec bot python -m app.covers enable default
docker compose exec bot python -m app.covers disable default
docker compose exec bot python -m app.covers upgrade
```

`upgrade` добавляет отсутствующие ключи текстов и статусов из шаблона; обновление также выполняется при запуске процесса ботов. `TYBEE_BOT_TOKEN` не заменяет токен уже созданной обложки: меняйте его в настройках этой обложки.

## Обновление панели в реальном времени

Панель держит одно WebSocket-соединение `/api/support/events` на вкладку. Сервер присылает только имя изменившейся области (`support`, `finance`, `staff`), а браузер сбрасывает соответствующие кэши запросов. Поэтому список обращений, диалог, счётчик непрочитанных и сводка финансов обновляются сразу после изменения, а не по таймеру.

Опрос остаётся резервным: при живом соединении — раз в 60 секунд, без него — раз в 15 секунд. Если соединение оборвалось, панель переподключается с нарастающей паузой (до 30 секунд), а также при возврате вкладки в фокус и восстановлении сети.

История сообщений открытого диалога не перезагружается: по сигналу панель догружает только новые сообщения (`?after_id=`) и дописывает их в конец. Отметка «прочитано» меняет только счётчики, поэтому она не сбрасывает переписку. Полная загрузка истории происходит лишь при открытии диалога и при подгрузке предыдущих страниц.

Ответы API и статические файлы сжимаются gzip (`GZipMiddleware`, от 1 КБ): JSON диалога уменьшается примерно в восемь раз. Если панель стоит за обратным прокси, включите там сжатие только для несжатых ответов, чтобы не сжимать дважды.

Сигналы публикуются в процессе панели, поэтому схема рассчитана на один процесс `uvicorn`. При переходе на несколько процессов или реплик шину нужно перевести на `LISTEN/NOTIFY` PostgreSQL либо Redis.

## Данные и резервное копирование

Сохраняйте вместе согласованные резервные копии базы PostgreSQL, `covers/`, `data/` и секретных настроек `.env`. В базе находятся заказы, сотрудники и история; в `covers/` — настройки и токены обложек; в `data/` — рабочие файлы. Копии содержат персональные данные и секреты, поэтому ограничьте доступ к ним и проверяйте восстановление.

Например, дамп базы при работающем Compose можно создать командой:

```bash
docker compose exec -T db sh -c 'pg_dump -U "$POSTGRES_USER" "$POSTGRES_DB"' > tybee-backup.sql
```

Для согласованной копии файлов и базы организуйте резервирование с учётом работающих процессов. Не удаляйте том `pgdata`, `covers/` или `data/` при обновлении. Команда `docker compose down -v` удаляет том базы.

Вложения Telegram обычно привязаны к идентификаторам файлов и исходной обложке; доступность зависит от Telegram и возможности использовать соответствующего бота. Исходящие файлы могут временно храниться для очереди доставки; недоставленные файлы могут требоваться для повторной отправки. Утилита `scripts.clear_old_support_attachments` имеет режим удаления: перед её применением необходимо остановить процессы, проверить очередь и сделать резервную копию.

## Обновление и эксплуатация

```bash
docker compose up -d --build
docker compose ps
docker compose logs -f --tail=100 bot site
```

Обновляйте `bot` и `site` вместе: они используют общие таблицы и очереди. При запуске приложение инициализирует и обновляет схему базы; перед обновлением сделайте проверяемую резервную копию и сначала проверьте обновление на копии данных. Не выводите секреты из `.env` в общедоступные журналы.

Доставка ответа идёт через соответствующий канал или обложку. При недоступности канала система не должна молча подменять его другой обложкой; причину недоставки ищите в диалоге и журналах. Состояние конкретной интеграции и возможность сквозной идентификации клиентов между Telegram и Avito необходимо проверять отдельно с командой интеграций.

## Локальная разработка

Для запуска вне Docker нужны Python 3.12, Node.js 22, PostgreSQL и заполненный `.env`. Укажите в `.env` адрес PostgreSQL, доступный с машины разработчика, например `POSTGRES_HOST=127.0.0.1`; значение `db` предназначено для сети Compose.

```bash
python3 -m venv .venv
. .venv/bin/activate
pip install -r requirements.txt -r site/requirements.txt
python -m scripts.run_bots
```

В другом терминале с активированным окружением:

```bash
DEV=true PYTHONPATH=.:site/backend python -m panel
```

Для разработки интерфейса в третьем терминале:

```bash
cd site/frontend
npm ci
npm run dev
```

Vite доступен на `http://localhost:5173` и проксирует `/api` на `127.0.0.1:8000`. Для проверки сборки интерфейса выполните `npm run build` в `site/frontend`. Клиентский бот работает через long polling: один и тот же токен не должен одновременно обслуживаться несколькими запущенными процессами polling.
